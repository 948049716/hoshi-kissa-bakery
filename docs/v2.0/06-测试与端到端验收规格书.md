## 3. L2 · 30 关配置静态压测规范

校验脚本在遍历 `levels_data.js` 全部 30 关时，必须逐关断言以下 5 条不变量：
1. **数量完备**：共 `3` 章，每章精确 `10` 关（`1-1`~`3-10` 连续不缺失）。
2. **矩阵矩形对齐与字符合法性**：`matrix` 每行长度完全一致，且只允许出现 `.` `#` `X` `G` `M` `B` `I`。
3. **预置坐标合法性**：每关 `presets` 的 `(r, c)` 均在界内且对应位置不是 `#` 或 `X`；凡是标记 `I` 的格子在 `presets` 中必须有且仅有 `frozen: true` 的猫饼，且非 `I` 格无冰封。
4. **可达性与连通性校验**：每关非冰封可滑可用格至少包含 `>= 8` 个 `.`/`G`/`M`/`B` 格，且使用 BFS 检查不存在被 `#` 和 `X` 完全孤立成“1 格死牢”（无法与任何格相邻）的无效单元格。
5. **星级分严格递增**：`0 < stars[0] < stars[1] < stars[2]`，且第 `1` 章不能包含 `M/B/I`（第 1 章仅 `.`/`#`/`X`），第 `2` 章不能包含 `B/I`。

## 4. L3 · `scripts/verify_minigame_e2e.mjs` 端到端验收场景

保留现有 `scripts/verify_minigame_e2e.mjs` 内的 `window.__WX_HARNESS__` 微信胶囊、安全区与 Web Audio 模拟环境，重写为以下 **8 大必测自动化验收场景**（任一失败直接退出非零码阻断 CI）：

1. **首屏大厅与模式清理校验**：
   - 启动即呈现选关大厅，存在第 1 章 `1-1` 至 `1-10` 节点；
   - 断言页面状态与按钮热区中**绝不存在** `mode_rush`（90秒狂欢）、`mode_zen`（悠闲经典）或旧 3 按钮模式卡。
2. **开局进关与纯上菜零分断言**：
   - 点击主 CTA 进入 `1-1`；
   - 通过触屏滑动手势执行 2 次有效 2048 滑动，并点击 1 次「🐾 揉面补料」按钮，断言盘格猫饼正常合成与新增，同时 **`gameState.score === 0`**。
3. **单击装盘、自动上菜与唯一加分断言**：
   - 在烤盘找到匹配某位顾客需求的亮金猫饼坐标并模拟轻点（位移 `< 5px`）；
   - 断言该盘格变空、托盘内对应槽出现猫饼；凑齐整单后触发 `flyingServe`，`gameState.score > 0`、`ordersServed >= 1`。
4. **双击托盘丢弃厨余桶与死盘脱困**：
   - 单击一颗猫饼放入托盘后，在同一托盘槽位连续快速点击 2 次（间隔 `120ms < 320ms`）；
   - 断言该托盘槽清空还原，且 `score` 保持不变。
5. **时间推进、星级结算与星尘持久化**：
   - 推进游戏时间至本关营业倒计时结束且已达 `star1` 分数；
   - 断言自动弹出 1~3 星结算面板，永久星尘 `bankStardust` 准确增加并解锁 `1-2`。
6. **吃茶小铺消费与能力生效验证**：
   - 在吃茶小铺购买 `C1` 菜价升级至 `Lv.1` 与「宽大木托盘」至 `Lv.1`；
   - 刷新页面重载 `wx` 本地存储，重新进入关卡断言托盘容量已变为 **`4` 格**且 `C1` 基础价已提升至 `36`。
7. **多视口胶囊避让与无裁切截图回归**：
   - 分别在 `375×667`（SE 紧凑竖屏）、`390×844`（全面屏含右上胶囊与底部安全条）、`1280×760`（桌面宽屏）三个分辨率下完成大厅、局内、结算与小铺截图；
   - 断言所有顶部导航按钮 `right <= menuRect.left - 8`、底部 Dock `bottom <= height - safeBottom`。
8. **零运行时异常与离线资源完整性**：
   - 全程监听 `console.error` 与 `pageerror`，断言异常数为 `0`；检查 `05-微信小游戏版本/assets/` 所有引用路径 100% 存在且主包总体积 `< 4 MB`。
